## Goal

The smallest useful LLM application: a question goes in, a prompt is built, an LLM answers, the answer comes back through typed models — as a plain Python function/CLI, no HTTP. This version is about learning to talk to an LLM *through a clean seam* so that everything built later (RAG, tools, agents) plugs into an interface you control rather than a vendor SDK scattered through the codebase.

**You'll have learned:** LLM API mechanics (tokens, context window, temperature, cost), prompt structure (system vs. user messages), how to wrap a provider behind an interface, how to test LLM-dependent code without calling the LLM, and — critically — what the model gets *wrong* without retrieval.

## Decisions

- **2026-08-23:** **Ollama (local) is the first `LLMClient` implementation; a hosted provider follows second.** Learner's rationale: free, offline, no API key to manage, and having a genuinely different second implementation is what proves the seam is a seam rather than a wrapper shaped like one vendor's SDK.
  - _Counter-risk recorded at decision time:_ a small local model's quality on Greek legal text is likely poor. Until a hosted implementation exists for comparison, a bad answer cannot be attributed between *the model* and *the retrieval* — which is exactly the attribution that step 10's baseline and [[V3 - First RAG System]]'s justification depend on. **Mitigation:** re-run the step 10 no-RAG baseline against the hosted provider once it exists, and treat the local-only baseline as provisional until then.
  - _Effect on step 1:_ the provider choice is now partly pre-decided. The comparison work shifts to (a) which local model to run under Ollama — size vs. Greek-language competence vs. what the machine can actually hold — and (b) which hosted provider comes second, chosen partly for being *unlike* Ollama in its API shape, since a seam validated against two similar APIs is not validated.
- **2026-08-22:** Defer introducing FastAPI/HTTP API layer. V1 (and subsequent versions) expose the application as plain Python functions/a CLI until a concrete need for an external-facing interface arises (e.g. when tools/agents in [[V8 - Tools and Structured Operations]] or later need to be called externally). Avoids HTTP plumbing distracting from the LLM/RAG concepts being learned first.
- **2026-08-22:** V1 ends with a **recorded no-RAG baseline** (step 10). Every architectural addition in this project should be justified by an observed failure or measurement, not by fashion — this baseline is the first instance of that discipline.

- **2026-08-29:** **Model: `ilsp/llama-krikri-8b-instruct`** (ILSP / Athena RC — Llama 3.1-8B continually pretrained on 56.7B Greek tokens, plus 21B English and 5.5B Greek-English parallel data; successor to Meltemi). Chosen over a general multilingual model because the open risk recorded on 2026-08-23 was *Greek-language competence*, and a Greek-specialized model attacks exactly that. Verified on the first probe: fluent native register and correct legal vocabulary. Hardware is not a constraint (M1 Max / 64 GB), so the choice was made on language quality, not size.
- **2026-08-29:** **Local inference means step 8 changes meaning.** There is no cost per token to log. The scarce resources are *latency* and *context window*, so step 8 becomes tokens-in/tokens-out, tokens/second, and wall-clock per call. The habit the step exists to build — knowing what each call costs before RAG multiplies prompt size — is preserved; only the unit changes. Revisit when the hosted provider lands and real pricing applies.

- **2026-08-30:** **The seam is `chat(list[Message]) -> ChatResponse`, at message level — not `answer_question(Question) -> Answer`.** Those are two layers: step 4 is infrastructure that knows HTTP and JSON and nothing about Greek law; step 5 sits above it with domain types. Consequence settled at the same time: **the caller owns the system prompt**, not the client — a hosted `AnthropicClient` must never carry a legal system prompt. Model name goes in the constructor (it is configuration); revisit only if the deferred Krikri-vs-Qwen comparison needs to swap models within one process.
- **2026-08-30:** **`ChatResponse` uses our field names, and each implementation translates into them.** The same concept has three names across providers — Ollama `done_reason`, OpenAI `finish_reason`, Anthropic `stop_reason`; Ollama `prompt_eval_count`, OpenAI `usage.prompt_tokens`, Anthropic `usage.input_tokens`. Naming ours after Ollama's would have made this a *wrapper*; picking our own makes it a *seam*. **In Java this is JDBC:** `Connection`/`ResultSet` is the interface and each driver maps its own wire protocol, with no `switch` on the vendor anywhere in application code. Applying the "could a hosted provider implement this?" test immediately caught one leak: **`eval_duration` was dropped**, because no hosted API reports generation time. Wall-clock measured around the call (`time.perf_counter()`) works for every provider.
- **2026-08-30:** **`typing.Protocol`, not `abc.ABC`.** Structural typing — closer to Go than to Java. `OllamaClient` neither imports nor inherits `LLMClient`, so there is no dependency edge from implementation to interface, which is [[Dependency Direction]]'s rule for free. The trade-off is real and was the argument for adding `mypy` the same day: conformance is checked **only** statically, so without a type checker the `Protocol` is decorative. `test_ollama_client_satisfies_the_protocol` passes under pytest no matter what — mypy is what actually asserts it.
- **2026-08-30:** **`OllamaClient.__init__` takes an optional `http_client: httpx.Client | None`.** Driven by a test, not by design: mapping tests had to reach into `client._http` to substitute a `MockTransport`, and a dependency that cannot be substituted is a hidden dependency. Defaults to `None`, so production behaviour is unchanged. **Java parallel:** inject `HttpClient` rather than `new`-ing it inside the service. It also settles the lifecycle question left open earlier — whoever constructs the client owns closing it.
- **2026-08-30:** **Test docstrings are mandatory** (see [[Agent Instructions]], Testing Policy 3). The explanation of what a test catches belongs in the test, not in a chat message that scrolls away. Retrofitted across all 33 tests on the day the rule was made. Rule of thumb: name the *consequence* ("would silently invert every number in the usage log"), not the mechanism ("checks the mapping").

- **2026-09-03:** **`Answer` carries no `sources` until [[V3 - First RAG System]].** The learner's call. An always-empty `list[SourceReference]` would be a field advertising a capability the system does not have — Golden Rule 6 — and adding it in V3 is a two-line change to a Pydantic model, not a retrofit. The same reasoning defers `citations` to [[V6 - Legal Structure and Citations]].
- **2026-09-03:** **Call measurements are nested — `Answer.metadata: AnswerMetadata` — not flattened onto `Answer`, and not logged as a side effect of `answer_question`.** The learner raised the question; the test that settled it was *who consumes `Answer`, and do they all want the same fields?* Three consumers, two shapes: the V1 CLI wants text **and** tokens (step 8); [[V7 - Evaluation Framework]] compares text and treats token counts as noise; [[V8 - Tools and Structured Operations]] serialises `Answer` to JSON for an external caller who should not see them. Three consequences of nesting: `Answer`'s top level stays about the law, so V3's `sources` and V6's `citations` sit beside `text` rather than beside `tokens_in`; [[V9 - Agentic Workflow]] turns one `answer_question` into many calls, and a nested model absorbs `call_count` and summed tokens where four flat fields would have to be renamed everywhere; and exclusion is one keyword, `model_dump(exclude={"metadata"})`. **In Java this is `ResponseEntity<T>`** — body and headers in one object, never flattened into one bag — or Spring's `Page<T>`, content plus metadata *about* the content.
  - _Third option considered and rejected:_ keep the measurements off `Answer` entirely and have `answer_question` log them, which is what step 8's wording literally suggests. Rejected on **testability**: a logged number needs `caplog` and string matching, a returned number is an equality check against the fake client. `answer_question` stays free of side effects and step 8 becomes *the CLI formats what it was handed* — the side effect moves to the edge, where side effects belong.
  - _Cost accepted:_ `AnswerMetadata` duplicates most of `ChatResponse`'s fields. Deliberate, and the same argument as 2026-08-30 — `ChatResponse` is infrastructure and must not leak upward. The alternative, `Answer.response: ChatResponse`, would have been less typing and a leak.
- **2026-09-03:** **`ChatResponse` gains `model: str`, taken from the response body — not from `Settings`.** Needed by `AnswerMetadata`, and it passes the 2026-08-30 test *could a hosted provider implement this?* unanimously: Ollama returns `model`, OpenAI returns `model`, Anthropic returns `model`. Config says what was *asked for*; hosted providers resolve aliases, so what was asked for and what answered are not always the same string. Concrete reason it is not speculative: step 10's saved baseline and the deferred Krikri-vs-Qwen comparison are worthless if the answers do not record which model produced them. _Naming caution:_ Pydantic reserves the `model_` **prefix**, so a field called exactly `model` is legal but `model_name` would be refused.
- **2026-09-03:** **New `application/` package; `Question`/`Answer` do not go in `domain/`.** `domain/` is Greek legislation — a Νόμος exists whether or not this software does. A *Question* is not part of Greek law, it is part of this application. Per [[V0 - Project Foundation]]'s rule, packages are created in the version that first needs them.
- **2026-09-03:** **`answer_question(question, client)` is a plain function with the client as a parameter** — no module-level global, no class field. In Java this is constructor injection moved to the method: the collaborator is explicit and substitutable, which is what makes the fake client work with no framework. **The module is the namespace** — `service.py` holding one function *is* the service; a `class QuestionAnsweringService` with a single method would be `public static void main` transliterated again (see [[Python for Java Developers]]). Revisit when V3 gives the function three collaborators (client, retriever, store) — that is when it earns being a class.
- **2026-09-03:** **The `AnswerMetadata(...)` block in `service.py` is written field by field on purpose, not `**response.model_dump()`.** That block *is* the boundary — the single place where an infrastructure type stops and an application type begins. If `ChatResponse` grows a field, the function keeps compiling and `Answer` stays unpolluted; auto-spreading would let anything added below leak upward silently. Same reasoning as the `_FINISH_REASONS` dict one layer down.

- **2026-09-05:** **The prompt is a Python module (`application/prompts.py`), not a template file.** A `.txt`/`.jinja` file loaded at runtime buys substitution and editing without a redeploy; neither is needed, and it costs `importlib.resources` plumbing plus a packaging entry so the file ships inside the wheel. Everything step 6 actually asks for — a home, a diff history, reviewability — a `.py` already has. _Revisit twice:_ [[V3 - First RAG System]], when the prompt grows a retrieved-context block, and [[V7 - Evaluation Framework]], when eval wants several prompt versions loadable side by side. It lives in `application/`, not `llm/`, by the 2026-08-30 decision that the caller owns the system prompt.
- **2026-09-05:** **The system prompt is written in Greek.** Krikri is Llama 3.1 continually pretrained on 56.7B Greek tokens and instruction-tuned in Greek; instructions in the target language are the ones its tuning followed most closely, and a Greek system prompt removes the language-drift failure where an English instruction pulls the answer into English mid-paragraph. _Cost accepted:_ when the hosted provider lands, the same prompt must be re-judged rather than assumed portable — a frontier model follows English instructions at least as well, and the comparison is then confounded by prompt language. Noted as debt.
- **2026-09-05:** **Each of the five prompt rules answers a *measured* failure, not a style preference.** Rules 1–2 (cite the provision; say «Δεν γνωρίζω τη διάταξη» rather than invent one) answer the 2026-08-29 probe's *zero* law numbers, articles and ΦΕΚ references. Rule 3 (no general formulations, no deflection to a lawyer) answers the same probe's vagueness tuning — it opened by declining and closed by recommending a lawyer. Rule 4 answers the verified ΟΑΕΔ/ΔΥΠΑ staleness. Rule 5 pins the output language. The scope boundary from [[Home]] is one sentence at the end, deliberately: repeating it is exactly the deflection rule 3 exists to suppress.
- **2026-09-05:** **`AnswerMetadata` gains `prompt_version: str`, sourced from the module constant.** Same argument as `ChatResponse.model` on 2026-09-03: step 10's saved baseline and [[V7 - Evaluation Framework]]'s regression comparison are worthless if an answer does not record *what produced it*, and the prompt is half of that. _Test written to defend it:_ `test_editing_the_system_prompt_requires_bumping_the_prompt_version` pins a sha256 of `SYSTEM_PROMPT` against `PROMPT_VERSION`. The failure it prevents is silent relabelling — editing the prompt without bumping leaves two different prompts' answers both stamped `"v1"`, and nothing at runtime notices.

- **2026-09-05:** **The seam raises its own exceptions; `httpx` never escapes `OllamaClient`.** Closes the debt that `test_http_error_reaches_the_caller_as_an_httpx_exception` was holding open on purpose since 2026-08-30. Without this, every caller — `service.py`, the V1 CLI, the [[V9 - Agentic Workflow]] loop — must `import httpx` to write a `try/except`, which welds the application to one transport and makes the hosted client a breaking change rather than a drop-in. The replacement test asserts the httpx type is *absent*, which is the only phrasing that also catches a **new** failure path added later without translation.
- **2026-09-05:** **The hierarchy's top split is transient vs. permanent, not one class with a `retryable` flag.** That is the only question a retry policy asks, so it is a branch in the type tree and `except TransientLLMError` becomes the whole policy — the language dispatches instead of an `if` reading a field. **This is Spring's `DataAccessException`** (`TransientDataAccessException` / `NonTransientDataAccessException` with a per-driver `SQLExceptionTranslator`), and it is the same JDBC argument recorded on 2026-08-30 for `ChatResponse` field names: `OllamaClient` is the translator, the hosted client will be the second one. Mapping: timeout / 429 / 5xx / connection-refused → transient; other 4xx / unreadable 200 body → permanent.
- **2026-09-05:** **`LLMProtocolError` exists because a 200 can still be unusable.** `body["prompt_eval_count"]` raises a bare `KeyError` when Ollama serves a prompt from its cache and omits the field — a real body, not a hypothetical. `KeyError('prompt_eval_count')` in a traceback reads as *"bug in our code"* and sends the next hour to the wrong layer. It is classified **permanent**: re-sending will not grow the field. One `except (ValueError, KeyError, TypeError)` covers all three shapes, because `json.JSONDecodeError` and Pydantic's `ValidationError` both subclass `ValueError`.
- **2026-09-05:** **`_translate_status` returns the exception instead of raising it.** Keeps `raise ... from error` at the call site, where the original is still in scope — and `from` is what sets `__cause__`, so the traceback reads *"the direct cause of"* rather than *"during handling of the above, another exception occurred"*, which looks like a bug in the handler.
- **2026-09-05:** **`Retry-After` parsing deliberately omitted.** Ollama never sends a 429, so parsing the header is code no provider in this project exercises — Golden Rule 6, and the same reasoning that rejected `httpx` "because async". The 429 → `LLMRateLimitedError` mapping stays, because step 7 exists to define behaviour for it. Add the parse when a real header appears.
- **2026-09-05:** **`answer_question` is unchanged; `LLMError` propagates.** This step gives failures a *shape*. What the application does about one is a separate concern that belongs at the edge — the same argument as the 2026-09-03 decision that kept measurement logging out of `service.py`.

- **2026-09-05:** **Retrying lives in a separate `RetryingLLMClient`, not inside `OllamaClient.chat`.** Two reasons, both concrete. *Measurement:* `duration_seconds` is taken around one attempt; retrying inside the client would report one attempt's latency while the user waited for three, corrupting step 8's numbers. *Reuse:* every future implementation would otherwise reimplement the same loop. It is the **Decorator pattern** — `RetryingLLMClient` *is* an `LLMClient` and *has* one, exactly `BufferedReader(new FileReader(f))` — and it is the first real proof the seam is a seam rather than one vendor's SDK reshaped: the wrapper composes with any implementation, including a second copy of itself, because it only ever talks to the `Protocol`.
- **2026-09-05:** **Hand-rolled retry loop, ~20 lines, instead of `tenacity`.** Golden Rule 3 — the concepts *are* the step: why exponential rather than fixed, why jitter, why a wall-clock budget rather than an attempt count. `@retry(wait=wait_exponential(), stop=stop_after_attempt(3))` spells those as keyword arguments and teaches the API instead of the idea. _Revisit at [[V9 - Agentic Workflow]]_, where agent loops make retry policy genuinely complex and hand-rolling stops paying. The loop is `while True`, not `for ... in range()`, because a `for` can finish without returning and mypy would then demand an unreachable `raise` to satisfy `-> ChatResponse` — the same reasoning as Java's "missing return statement".
- **2026-09-05:** **Full jitter (`rng.uniform(0, ceiling)`), and the *ceiling* is what doubles.** Backoff alone spreads retries over time; jitter spreads them across *callers*. Without it, N clients failing at the same instant all retry at 0.5s, then all at 1.0s — a thundering herd that re-floods a provider just as it recovers. _Left out:_ a `max_backoff_seconds` cap, which only matters at attempt counts this project does not reach yet.
- **2026-09-05:** **A wall-clock budget (`budget_seconds`) alongside `max_attempts`, checked *before* sleeping.** An attempt count cannot bound how long a call takes: a timeout has already consumed the full `request_timeout` before it raises, so 3 attempts at a 30s timeout is a 90-second failure that a caller with a deadline experiences as a hang. Checking after the sleep would enforce the budget only once it was already blown.
- **2026-09-05:** **`sleep` and `rng` are injected constructor parameters with production defaults.** Third instance of the same rule (`http_client` on 2026-08-30, the client parameter on `answer_question` on 2026-09-03): a dependency that cannot be substituted is a hidden dependency. Concretely it is the difference between a 1.5-second test that asserts nothing about the delay and an instant one that asserts the backoff ceiling doubled. `Callable[[float], None]` is `Consumer<Double>`; the test's `RecordingSleep` uses `__call__` to make an instance callable, which is a functional interface implemented by a class rather than a lambda.

## Tools & Alternatives Considered

- **2026-08-30: HTTP client — `httpx`, over `urllib.request` and over the `ollama` SDK.**
  - _Rejected reason:_ "httpx supports async." Async belongs to [[V10 - Concurrent Execution]], whose own rule is *profile first*. Choosing a dependency for a capability no measured problem requires is the speculative-complexity failure Golden Rule 6 exists to prevent. Async is a free bonus here, not a justification.
  - _Actual reason — step 7._ Typed exceptions (`httpx.TimeoutException`, `httpx.HTTPStatusError` carrying `.response.status_code`) versus urllib's `HTTPError`, which is simultaneously an exception and a response object, and whose timeouts surface inconsistently as `URLError`-wrapped `socket.timeout` or bare `TimeoutError`. Retry logic that must sniff `e.reason` will eventually retry the wrong thing.
  - _Second reason:_ httpx separates connect/read/write timeouts. Against a local Ollama that distinction is real — connect should fail fast (localhost is up or it isn't) while read must be patient, because an 8B model generating ~500 tokens legitimately exceeds 30s. One shared timeout number cannot express that.
  - _Cost accepted:_ for the step 3 probe alone, `urllib.request` costs zero dependencies and ~6 extra lines. The dependency is genuinely being bought for step 4's client, not for the probe.
  - _`ollama` SDK rejected for step 3_ (revisit at step 4): it returns a parsed object, hiding the wire format that step 3 exists to expose. See [[LLM Chat API]].

- **2026-08-30: Static type checking — `mypy`, added now rather than deferred to [[V12 - Production-Oriented System]].**
  - _Trigger:_ two failures in one session that the whole existing toolchain missed — `from pyparsing import Literal` (editor auto-import of the wrong module) and `from greek_law.models import ...` (missing the `llm` package segment). Both left `greek_law.llm` unimportable; `ruff check`, `ruff format --check` and `pytest` all passed. The project's own bar is *"a real requirement, a measured failure, or a learning objective"* — two measured failures clears it.
  - _Root cause worth naming:_ **Python has no compile step.** `import` is an executable statement resolved when the line runs, so nothing validates it beforehand. `ruff` is a linter and never resolves imports across modules; `pytest` only catches what a test happens to import, and no test imported `greek_law.llm`.
  - _Second reason, specific to step 4:_ `LLMClient` is a `typing.Protocol`, and structural conformance is **only ever checked statically**. Without a type checker the seam is decorative — nothing verifies that `OllamaClient` satisfies it, and nothing will verify the hosted client later. `mypy` is what makes the `Protocol`-over-`ABC` choice safe.
  - _Config notes:_ `plugins = ["pydantic.mypy"]` is **required**, not optional — a Pydantic `__init__` is typed `**data: Any` by default, so without it mypy would accept a misspelled field like `token_out=`. `explicit_package_bases = true` makes `tests/` modules resolve as `tests.*` for the strictness override **without** adding an `__init__.py`, preserving the decision recorded in [[Python Packages and Imports]].
  - _First run: 30 errors, 0 real bugs._ 24 were missing annotations in tests (fixed by the override); the remaining 6 are deliberate type violations inside `pytest.raises(ValidationError)` blocks, suppressed with `# type: ignore[<code>]`. Worth noting the inversion: **mypy flagging a negative test is evidence the test is well-aimed** — silence there would mean the call wasn't actually type-incorrect and the asserted failure couldn't occur. `strict` bundles `warn_unused_ignores`, so a suppression that stops being needed is reported rather than rotting (better than `@SuppressWarnings`).
  - _Cost:_ `src/` and `scripts/` were already clean under `strict`. Wired as `poe typecheck`, referenced from `poe lint`; deliberately **not** in `poe format`, since mypy never modifies files.

- **2026-09-03: `pythonpath = ["."]` added to `[tool.pytest.ini_options]`**, so `tests/fakes.py` imports as `tests.fakes` under both tools. Without it the two tools disagree about the module's name: mypy, with `explicit_package_bases`, calls it `tests.fakes` (the same naming the `module = ["tests.*"]` override already relies on), while pytest's `prepend` import mode puts `tests/` itself on `sys.path` and calls it plain `fakes`. Putting the project root on the path makes `tests.fakes` correct for both. **Java parallel:** Maven knows `src/test/java` is a source root because the layout declares it; Python has no such convention, so the runner has to be told. _Alternative considered:_ a `conftest.py` — rejected because it has the identical naming problem and adds a file. `__init__.py` in `tests/` stays out, per [[Python Packages and Imports]].

### Technical debt

- ~~**`httpx` leaks through the seam (2026-08-30).**~~ **Resolved 2026-09-05** — `llm/errors.py` plus translation in `OllamaClient.chat`. Kept for the record: the placeholder test pinning the wrong behaviour did its job, failing exactly when the fix landed.
- **Retries are silent (2026-09-05).** `RetryingLLMClient` logs nothing, so a call that succeeded on its third attempt is indistinguishable from one that succeeded immediately — except in a latency number nobody is watching yet. Step 8 records `duration_seconds` per call and will make the anomaly visible without explaining it; the fix is a log line per retry, which belongs with [[V11 - Observability]].
- **`Retry-After` still not honoured (2026-09-05).** `LLMRateLimitedError` backs off on the same curve as everything else, ignoring what the provider asked for. Harmless while Ollama is the only provider (it never sends a 429); wrong the day a hosted provider lands, which is also the day the header becomes testable.
- **Seam unproven with a single implementation.** An interface with one implementation is a guess about what varies. It stays a guess until the hosted provider lands — expect the `LLMClient` interface to change when it does, and treat that change as the design working, not failing.
- **Provisional baseline.** Step 10's no-RAG answers are provisional while only the local model exists (see the 2026-08-23 decision).
- **Machine-specific port committed as the default (2026-08-30).** `ollama_base_url` in `config.py` and `OLLAMA_BASE_URL` in `.env.example` are both `11435`, this machine's Ollama port. The conventional default is `11434`, and per [[Configuration]] the per-machine value belongs in `.env` alone. Harmless today, "works on my machine" the moment anyone else clones it.
- ~~**No type checker (2026-08-30).**~~ **Resolved same day** — `mypy` added, see Tools & Alternatives. Kept for the record: `ruff` is a linter and a formatter; it does not resolve imports or check types. Two consequences hit on the same day: (a) `from pyparsing import Literal` — an editor auto-import of the wrong module — was committed in a state where the package could not be imported at all, and `poe lint` *and* `poe test` both passed; (b) the `LLMClient` `Protocol` in `llm/client.py` is unenforced documentation, since structural conformance is only ever checked statically. `mypy` or `pyright` closes both. Interim habit: `uv run python -c "import greek_law.llm.models, greek_law.llm.client, greek_law.llm.ollama_client"` as a two-second "does it compile" smoke test after touching a module.
- **Two empty modules committed (2026-08-30).** `llm/client.py` and `llm/ollama_client.py` went into `51d8f5a` at 0 bytes. Nothing imports them yet, so nothing complained — the same blind spot as above.

When the hosted implementation lands, prompt language becomes a confound in the model comparison — the same prompt may not be the best prompt for a frontier model, and a worse score would be unattributable between model and prompt language.
